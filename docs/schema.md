# Схема termbase

Основной файл: `data/termbase.csv`.

| Поле | Обязательное | Описание |
|---|---:|---|
| `id` | да | Стабильный идентификатор записи вида `ATB-0001` |
| `term_en` | да | Английский термин в словарной форме |
| `abbreviation` | нет | Сокращение или общеупотребительное обозначение |
| `term_ru_candidate` | да | Предлагаемый русский эквивалент |
| `category` | да | Тематическая категория |
| `term_type` | да | Тип понятия: component, system, process, parameter и т. п. |
| `source_id` | да | Идентификатор источника |
| `translation_status` | да | `candidate`, `approved`, `rejected` или `deprecated` |
| `definition_en` | нет | Определение из допустимого открытого источника |
| `usage_note_ru` | нет | Редакторское примечание на русском языке |
| `product_scope` | нет | Область применения в конкретном изделии или проекте |
| `confidence` | да | `high`, `medium` или `low` |
| `source_url` | да | Ссылка на источник |

## Правила

1. Одна строка описывает одно значение термина.
2. Омонимы и одинаковые сокращения не объединяются: контекст фиксируется через `category`, `term_type`, `source_id` и `usage_note_ru`.
3. Автоматическая принудительная замена разрешена только для `approved`.
4. Термины, импортированные из внешнего источника без утверждённого русского эквивалента, получают статус `candidate`.
5. Определения нельзя копировать из закрытых стандартов, если лицензия не разрешает распространение текста.
6. `id` после публикации не переиспользуется для другого понятия.

## Нормализация

- UTF-8;
- разделитель CSV — запятая;
- переносы строк внутри полей допускаются только с корректным CSV-экранированием;
- английский термин хранится без конечной точки;
- сокращения сохраняют нормативный регистр;
- категории и статусы записываются в `snake_case`.
